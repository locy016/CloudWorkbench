# 云端工作台 Android 开发计划

手机和平板用于跟进云端 Codex 任务、处理审批、补充现场资料和判断服务器是否需要介入。现有能力包括项目和会话、运行状态、审批、网页取材、图片附件和离线语音。APP 通过专用 SSH 密钥访问固定业务网关。

## 开发顺序

| 阶段 | 交付 | 验收 |
| --- | --- | --- |
| 先完成退役 | 正式版本移除旧配对入口，私有更新源只提供当前版本 | 同签名从 0.4.40 升级后自动连接，菜单可打开云端、会话、浏览和设置，旧授权页缺席。私有更新支持鉴权和分段下载 |
| 任务续接 | 首页集中显示待审批、执行中和需重试事项，打开即定位项目及会话。按项目及会话保留本机草稿和待发送附件，标明发送结果。短时切换后台时保留 SSH 连接和事件流 | 覆盖 Wi-Fi 切换、后台返回和进程重启。恢复同一任务和草稿，重试不产生重复任务。反复提交同一审批只生效一次 |
| 再改善开发交接 | 在会话里集中查看网页选区、截图和图片来源。试做问题复现与结果交接模板，并沿用现有会话发送流程 | 用最近的真实开发任务复测。用户能在手机上选定项目、补齐资料，回到电脑后继续同一会话。记录完成耗时和切换次数 |
| 验证后扩展运维 | 从运行指标、服务状态与最近错误入手，先提供可复制的只读诊断摘要。根据使用记录决定是否增加固定检查 | 能判断故障范围和下一步。诊断卡显示检查时间与数据来源，执行变更仍通过明确审批 |

新任务入口复用现有事件、会话和审批。若使用记录显示确实错过了需要处理的消息，再单独评估 Android 后台提醒的时效、耗电和连接方式。

## 如何发现应用场景

先回放最近一次移动审批、一次网站排查和一次网页或图片取材。按实际操作顺序记录从打开 APP 到任务结束的步骤，再观察两周真实使用。个人自用可以记简短的事件日记，也可以使用已脱敏的现有服务状态和测试结果核对现象。 [情境研究与观察](https://www.gov.uk/service-manual/user-research/contextual-research-and-observation)

| 记录项 | 提问 |
| --- | --- |
| 触发与目标 | 在什么情况下拿起手机？要看到什么结果才算处理完？ |
| 现有路径 | 打开了哪些页面或工具？哪一步必须换到电脑或服务器终端？ |
| 代价与风险 | 花了多久？是否发生等待、中断、误批、重复提交或资料丢失？ |
| 证据与试验 | 同类问题出现几次？用现有界面做一次小改动，能否少走一步或避免一次失败？ |

优先验证高频、高影响或反复迫使用户换设备的任务。先记录原流程，再用同类型任务复测耗时、成功率和设备切换次数。场景记录只包含任务类型、结果和耗时，省去私钥、令牌、命令正文和客户资料。

### 第一轮待验证的场景

- **离开电脑后继续跟进。** 回到 APP 能直接找到最新的任务结果或待审批请求。用前后台切换后的定位耗时和重发次数衡量。
- **看到故障时带着证据交接。** 从网页、截图或图片选中信息，补充一句说明并发给指定项目。用资料脱离原会话的次数和回到电脑后重新解释的次数衡量。
- **收到异常后判断是否需要登录服务器。** 手机先查看服务状态、采集时间和近期异常。用能否在手机上完成初步分流衡量。
